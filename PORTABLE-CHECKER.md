WireVeil Checker — портативная проверка подписок
================================================

Запуск
------

1. Распакуйте архив в обычную папку.
2. Запустите WireVeilChecker.exe. Установка и права администратора не нужны.
3. Для NekoBox выберите вкладку «NekoBox / sing-box», вставьте URL подписки,
   её текст или выберите локальный файл.
4. Нажмите красную кнопку «Сделать заебись».
5. Сохраните «годные» серверы в TXT и импортируйте файл в NekoBox либо
   нажмите «В буфер годные» и вставьте ключи в клиент.

Для пакетной диагностики Clash-конфигураций откройте вкладку
«Mihomo / OpenClash». Обе вкладки используют отдельные настройки, результаты и
локальные процессы; переключение между ними не останавливает текущую проверку.

Как проходит проверка
---------------------

Приложение запускает вложенный sing-box только на время теста и отправляет
реальный HTTPS-запрос через каждый сервер. Обычный ICMP-ping не используется:
многие рабочие серверы его блокируют, а открытый порт сам по себе не доказывает,
что прокси передаёт трафик. По умолчанию каждый узел должен успешно пройти два
независимых прогона. Проверка выполняется из текущей сети этого компьютера.
Весь список появляется в таблице сразу, а задержка каждого узла обновляется
сразу после ответа, не дожидаясь завершения остальных серверов.
Нажатие на любой заголовок таблицы сортирует колонку по возрастанию, повторное
нажатие — по убыванию. Для результата теста это переключает меньший/больший ping;
тайм-ауты и ещё не проверенные строки остаются внизу.

Несколько строк выбираются с Ctrl или Shift. Кнопка «Копировать выбранные» или
Ctrl+C помещает соответствующие share-ссылки в буфер для вставки в NekoBox.

В выпадающем меню «Проверка сайтов» галочками можно одновременно выбрать
ChatGPT, YouTube, GitHub, Google, Discord и Telegram Web. Кнопка «Проверить
доступ» отправляет небольшие HTTPS-запросы через каждый зелёный сервер и
показывает для каждого выбранного сайта отдельную сортируемую колонку с
результатом и задержкой. Для широкой таблицы предусмотрена горизонтальная
прокрутка. Это не заменяет общий ping: зелёный цвет означает, что прокси в целом
передаёт HTTPS-трафик, а колонки сайтов — что доступны именно эти домены. При
изменении набора сайтов старые результаты очищаются. Cookies, пароли и токены
пользователя в запросы не добавляются. Поэтому ответ ChatGPT HTTP 401/403
показывается как «домен отвечает» и считается успешной сетевой доступностью:
запрос дошёл до ChatGPT, но приложение не пытается войти в аккаунт и не обещает
готовую авторизованную браузерную сессию.

После проверки сайтов включается умная итоговая сортировка. Серверы, открывшие
все выбранные сайты, становятся зелёными и поднимаются наверх; частичный доступ
показывается жёлтым, отсутствие доступа — красным. Обычный низкий ping больше не
делает сервер годным, если выбранные сайты через него не открываются. Кнопки
«Сохранить годные», «В буфер годные» и тест скорости после этого используют
только серверы, прошедшие все выбранные сайты.

Красная кнопка «Сделать заебись» предназначена для запуска без настройки:
достаточно вставить подписку и нажать её. Приложение само выполнит ping, проверит
скорость зелёных серверов, включит и проверит все сайты, применит умную
сортировку и скопирует итоговые годные share-ссылки в буфер обмена.
Обычный стартовый экран оставляет на виду именно эту кнопку; ручные тесты,
тайм-ауты, потоки, порог ping и выбор сайтов находятся в «Дополнительных
настройках».

Параметры и поле подписки автоматически сохраняются в файле
`WireVeilChecker.config.json` рядом с приложением и загружаются при следующем
запуске. Сохраняются прогоны, тайм-аут, потоки, порог ping, авторежим, интервал,
выбранные сайты, состояние расширенной панели, а также URL или вставленные ключи
подписки. Конфиг остаётся локальным и исключён из Git. Ключи хранятся в нём
обычным текстом, поэтому не публикуйте и не передавайте этот файл посторонним.
Кнопка «Очистить» рядом с подпиской удаляет текст и сохранённое значение. В поле
работают Ctrl+C, Ctrl+V, Ctrl+X и Ctrl+A при русской и английской раскладке, а
также Ctrl+Insert и Shift+Insert.

Карточка «Полный автоцикл» повторяет тот же полный цикл через выбранное число минут:
ping, скорость, все сайты, умную сортировку и автоматическое копирование.
Для URL-подписки перед каждым прогоном заново загружается её актуальное содержимое.
Отсчёт начинается после завершения текущего прогона и каждую секунду показывается
в интерфейсе; кнопка «Стоп» выключает и текущую проверку, и таймер.

Карточка «Контроль доступности» работает отдельно и заметно быстрее.
После «В буфер годные» приложение запоминает скопированный набор и по умолчанию
раз в 30 минут делает только один HTTPS-прогон. Карточка показывает точный
обратный отсчёт, число серверов на контроле и кнопку «Проверить сейчас».
Приложение не загружает полную подписку заново, не измеряет скорость и не проверяет сайты. В таблице
сразу видно, какие из ранее скопированных серверов доступны. Исходный набор не
сокращается автоматически, поэтому временно недоступные серверы проверяются снова.

Пинг и скорость — разные измерения. Пинг показывает задержку HTTPS URL-test в
миллисекундах. Кнопка «Скорость зелёных» становится доступна только после
проверки доступности и загружает через каждый итоговый зелёный сервер тестовый файл
Cloudflare размером 1 МБ. Результат выводится отдельно в Мбит/с. Красные, жёлтые
и не завершившие все прогоны серверы в тест скорости не попадают. Проверка
скорости расходует примерно 1 МБ трафика на каждый зелёный сервер. Он запускается
отдельной ручной кнопкой либо как часть полного цикла «Сделать заебись» и его
авторежима.

Поддерживаются share-ссылки VLESS, Trojan, Shadowsocks, VMess, Hysteria2 и TUIC,
включая обычные TXT- и Base64-подписки. Клиентские JSON/YAML-конфигурации без
share-ссылок, WireGuard и AmneziaWG в эту версию не входят.

Безопасность
------------

Подписка и результаты никуда не отправляются, кроме загрузки указанного URL и
тестовых HTTPS-запросов через проверяемые прокси. Ключи содержат учётные данные:
не публикуйте сохранённые файлы и диагностические отчёты. Бесплатный прокси может
видеть незашифрованный трафик и перестать работать в любой момент.

Mihomo / OpenClash: пакетная диагностика
----------------------------------------

Вторая вкладка принимает до 200 независимых источников за один запуск:

- одиночный URL или список URL (один адрес на строку);
- несколько локальных файлов `.yaml`, `.yml` или `.txt`;
- вставленный Mihomo/Clash YAML с отдельным именем.

TXT-файл, в котором каждая непустая строка содержит HTTP(S)-URL, автоматически
разворачивается в отдельный URL-источник для каждой строки. Обычный TXT с YAML
остаётся одним файловым источником. Во всех окнах ввода работают Ctrl+C,
Ctrl+V, Ctrl+X и Ctrl+A при русской и английской раскладке, Ctrl+Insert,
Shift+Insert, кнопка вставки и контекстное меню правой кнопки мыши.

Каждый источник остаётся отдельной строкой и получает устойчивый `source_id`.
Его можно переименовать, удалить или выбрать для отдельного прогона. Кнопка
«Проверить все» повторно загружает каждый URL, разбирает источники независимо и
не прерывает пакет из-за одного битого файла. Список сохраняется рядом с
приложением в `WireVeilChecker.mihomo-sources.json`; этот файл может содержать
приватные URL, пути и вставленный YAML. Он исключён из Git, получает максимально
ограниченные доступные файловые права и не должен публиковаться. «Очистить
список» удаляет только локальные настройки, но не исходные файлы и не удалённые
подписки.

Поддерживаются Mihomo/Clash YAML и proxy-provider YAML с корневым
`proxies: [...]`. Поля узла сохраняются без преобразования, включая Reality,
TLS, WebSocket, gRPC и другие transport options. Из полного `config.yaml`
берутся только `proxies`: пользовательские `dns`, `tun`, `rules` и
`external-controller` никогда не запускаются. Внешний `proxy-providers` без
встроенного списка отмечается `EXTERNAL_PROVIDER_NOT_EXPANDED`. Списки share-URI
и Base64 во второй вкладке намеренно не конвертируются и получают
`UNSUPPORTED_FORMAT`; для них предназначена первая вкладка.

URL загрузки ограничен 5 МБ и проверяется перед каждым запросом и редиректом.
Локальные, loopback, link-local, служебные и private IP блокируются, чтобы
подписка не превращалась в запрос к внутренним сервисам компьютера. Полный URL
с query-токеном не попадает в интерфейс отчёта или ошибки.

Как Mihomo проверяет узлы
-------------------------

Приложение запускает вложенный `mihomo.exe` во временной папке на этом же
компьютере. API привязан к случайному порту `127.0.0.1`, защищён случайным
секретом; `allow-lan` выключен. TUN, системный прокси, маршруты Windows,
firewall, рабочий OpenClash на роутере и его конфигурация не изменяются.
Временный процесс останавливается и папка удаляется после завершения, по кнопке
«Стоп» и при закрытии приложения.

Узел считается передающим трафик только после минимум двух независимых HTTPS
URL-test через `/proxies/{name}/delay`: Google `generate_204` и резервный
Cloudflare `generate_204`, с проверкой ожидаемого HTTP 204. Ping и простое
TCP-подключение не используются. Одинаковые фактические конфигурации в разных
источниках тестируются один раз; в результатах они остаются привязанными ко всем
исходным `source_id`. Хэш учитывает credentials, SNI, transport, fingerprint,
Reality и obfs, но не косметическое имя.

После успешного базового HTTPS можно проверить ChatGPT, Instagram, Spotify,
Telegram Web, YouTube, GitHub и Discord. Статусы означают:

- `good` — базовый HTTPS и все выбранные сервисные URL доступны;
- `partial` — базовый HTTPS работает, но часть сервисов недоступна;
- `failed` — требуемые HTTPS-прогоны не пройдены;
- `unsupported` — протокол или параметры не поддержаны / отклонены Mihomo;
- `not_tested` — тест не выполнялся, например, из-за отмены.

Это проверка конкретных HTTPS URL, а не аккаунта или всего приложения. Она не
гарантирует авторизацию, мобильный клиент, CDN, воспроизведение видео и музыки,
UDP или QUIC. Результат зависит от маршрутизации Windows: чтобы измерять именно
сеть провайдера, перед запуском отключите промежуточный VPN и убедитесь, что ПК
выходит через нужный роутер.

Диагностический ZIP (схема JSON v1)
----------------------------------

«Экспорт отчёта» создаёт
`WireVeil-Mihomo-Report-YYYYMMDD-HHMMSS.zip` с тремя файлами:

- `report.json` — машиночитаемая схема `schema_version: 1`, сведения о локальном
  runtime и параметрах теста, источники, уникальные узлы, provenance, базовые и
  сервисные результаты, нормализованные коды ошибок и totals;
- `summary.md` — сводка по источникам и статусам, частые ошибки и явно
  обозначенные диагностические предположения;
- `nodes.csv` — UTF-8 with BOM, одна строка на `(source_id, node_id)`, отдельные
  статусы/задержки выбранных сервисов.

Стабильные поля верхнего уровня `report.json`: `schema_version`, `generated_at`,
`engine`, `test_environment`, `sources`, `nodes`, `totals`. Узел содержит только
хэш `node_id`, список `source_ids`, безопасные имена, протокол, endpoint, статус,
`base_https`, `services`, `error_code` и `error_summary`. UUID, пароли, токены
подписок, приватные ключи и полная конфигурация прокси в ZIP не записываются.
Поэтому из одного отчёта нельзя восстановить рабочую подписку; для изменения
самой конфигурации нужен исходный локальный YAML.

Приватный экспорт YAML
----------------------

«Приватный YAML рабочих…» формирует отдельный `proxies: [...]` со всеми
параметрами узлов со статусом `good`. «Приватный YAML по источникам…» создаёт
отдельный файл для каждого источника и сохраняет provenance. Коллизии имён
устраняются безопасным суффиксом. Эти файлы содержат реальные UUID, пароли и
ключи, никогда не добавляются в диагностический ZIP и не должны передаваться в
чат или публиковаться.

Текущие ограничения Mihomo-вкладки
----------------------------------

- Не разворачиваются внешние `proxy-providers` и Base64/share-URI.
- Экспорт по источникам создаёт provider-style YAML `proxies: [...]`; остальные
  секции исходного полного config не переносятся.
- Пропускная способность не измеряется; задержка HTTPS не выдаётся за скорость.
- Offline CI подменяет API Mihomo. Реальный сетевой smoke test выполняется
  отдельно на Windows и зависит от доступности внешних тестовых URL.
